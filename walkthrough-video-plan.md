# MC 451 Final Portfolio — Walkthrough Video Plan

> Production plan for a screencast that walks students through the final-portfolio publishing pipeline: render → git push → enable GitHub Pages → submit to Blackboard.
>
> Target length: **8–12 minutes total**. One continuous video (not a series). Hosted on YouTube as Unlisted; URL goes in the assignment's Blackboard module. Optional second cut: a 2-minute "tl;dr" at the top for students who just want the steps.

---

## Production model

- **Voiceover:** Orator + your fine-tuned F5 voice. Same pipeline used for the BMS billboards.
- **Visuals:** Real screen recordings + the live example repo at `apleith.github.io/mc451-final-project-example/`.
- **Editing:** DaVinci Resolve / Premiere / ffmpeg — your call.
- **Captions:** Auto-generated by YouTube + a 5-min editor pass for typos.

Per the no-fabrication rule, every screen shown must be a real capture from your machine or the live web. Don't reconstruct UIs in slides.

---

## What you film vs. what Orator narrates

Owner captures (real, on-screen):

1. RStudio with the project open
2. Terminal running `quarto render`
3. The `docs/` folder filling with output
4. The live HTML preview (`docs/index.html` opened in browser)
5. The PDF preview (`docs/[Title].pdf` opened in browser)

9. github.com Settings → Pages — enabling
10. The live URL loading at `apleith.github.io/...`
11. Blackboard — submitting the PDF + URL

Orator narrates (script below). All recorded once, edited as voiceover.

## Voice script (Orator-ready)

The full script is below. Each numbered section corresponds to a screen recording segment listed in the shot list. The voiceover is timed for ~145 wpm — roughly the rate Orator's F5 model produces with the APLeith voice. Estimated total: ~9 minutes.

### Segment 1 — Cold open (0:00–0:30)

> Hi everyone. This is Dr. Leith. By the end of this video, your final portfolio will be a live website on the internet, plus a PDF you can submit to Blackboard. Total time, start to finish, is about ten minutes. The pipeline is one terminal command, one git push, and one click in GitHub. Let's go.

### Segment 2 — Rendering with one command (0:30–2:00)

> Open your final-project folder in RStudio. Make sure your `coding_data_clean.RDS` file is in the folder, and that you've already downloaded `apa.csl` per the README. In the RStudio Terminal — not the Console, the Terminal — type `quarto render`. That's it. Quarto reads your `_quarto.yml` config, runs every R code chunk, builds the figures and tables, and writes the website plus the PDF into a folder called `docs`. While it's rendering, we'll see two passes through your code — one for the HTML site, one for the LaTeX PDF. The PDF pass takes longer. When you see the line `Output created: docs/index.html`, you're done.

### Segment 3 — What rendering produced (2:00–3:00)

> Inside the `docs` folder you'll find every file you need to publish. Open `index.html` in your browser to preview the website. Click through the sidebar — abstract, introduction, methodology, results, discussion, references. Notice the search box at the top, and the dark mode toggle. The PDF is in the same folder, named after your study title. Open it. Notice that every figure, every table, every chi-square value is identical between the two outputs — same source files, two formats. If anything looks broken at this point, fix it now before publishing. The most common issues are unrendered citation keys (you'll see `[?@author2020]` instead of a real author name) and wrong variable names in code chunks.

### Segment 4 — Setting up the GitHub repo (3:00–4:30)

> Now we publish. Go to github.com and sign in. If you don't have a GitHub account yet, create one. Click "New Repository." Name it `mc451-portfolio`. Set it to Public — and yes, your project must be public for GitHub Pages to work on a free account. Don't initialize it with a README, because you already have files. Click "Create Repository." GitHub will give you a page with setup instructions. We're going to use the second block, the one for an existing folder.

### Segment 5 — Pushing the code (4:30–6:00)

> Back in the RStudio Terminal, run these commands one at a time. First, `git init` — this turns your folder into a git repository. Second, `git add .` — the dot means "add everything." Third, `git commit -m` followed by a quoted message — let's say "Initial commit." Fourth, `git remote add origin` followed by your repo's URL from GitHub. Fifth, `git branch -M main`. Sixth, `git push -u origin main`. The first time you push, GitHub may ask you to authenticate — either through a browser popup or by entering a Personal Access Token. Once it succeeds, refresh your GitHub repo page in the browser. You'll see all your files now live on GitHub.

### Segment 6 — Enabling GitHub Pages (6:00–7:30)

> Now the magic step. On your repo page, click "Settings" at the top. In the left sidebar, scroll down and click "Pages." Under "Build and deployment," set the Source dropdown to "Deploy from a branch." Branch is `main`. The folder dropdown is critical — set it to `/docs`, not `/(root)`. Click "Save." GitHub will start building your site. It usually takes one to three minutes. While that's happening, you'll see a yellow status indicator. When it's green, your site is live. Your URL will be `https://YOUR-USERNAME.github.io/mc451-portfolio/`. Copy that URL — you'll paste it into Blackboard in a minute.

### Segment 7 — Verifying the live site (7:30–8:30)

> Open your live URL in a private or incognito browser window. This step is non-negotiable. A private window verifies that the site works for someone who isn't signed into your GitHub account — which is the only thing that matters for grading. Click through every sidebar section. Open every figure. If anything is missing or broken, you'll see it now, while you have time to fix it. The most common issue is a forgotten `quarto render` after a last-minute edit — meaning the live site shows your old work. If that happens, run `quarto render`, `git add .`, `git commit -m "Update"`, `git push`. Refresh the live site after two minutes.

### Segment 8 — Submitting on Blackboard (8:30–9:00)

> Last step. On Blackboard, open the Final Portfolio submission. Two items go in. First, attach the PDF from your `docs` folder, renamed to `Lastname_FinalPortfolio.pdf`. Second, paste your live URL into the text box. Submit. You're done.

### Segment 9 — Updating after first publish (9:00–9:30)

> Every time you make a change after this — fixing a typo, adding a citation, anything — the update cycle is the same: `quarto render`, `git add .`, `git commit -m "describe what you changed"`, `git push`. GitHub Pages updates within two minutes of every push. You can keep iterating right up until the deadline.

### Segment 10 — Outro (9:30–9:45)

> Office hours, my email, and the Discord are all in the syllabus and the README. If you get stuck, ask early — most issues are fixed in two minutes if you ask before midnight on the deadline. Good luck.

## Production order

1. **Build the example you'll show on screen.** Already done — at `apleith.github.io/mc451-final-project-example/`.
2. **Capture all 9 screen recordings.** In one sitting if possible; the cursor pacing stays consistent. OBS Studio or built-in Windows Game Bar work fine. Capture at 1920×1080.
3. **Generate Orator narration.** Drop the voice script (above) into Orator with the `--audio-only` flag. Save as `voiceover-walkthrough.wav`.
4. **Composite in your editor of choice.** Layer narration over screen recordings; speed up boring waits (renders, GitHub builds) to 4×–8×.
5. **Add captions.** Upload to YouTube Unlisted; auto-captions handle ~95% of the work; spot-fix the technical terms (Quarto, kableExtra, longtable).
6. **Pin the YouTube URL in the Blackboard module** alongside the assignment.

## Optional 2-minute "tl;dr" cut

Same script, condensed:

> Open your project. In the Terminal: `quarto render`. That builds your PDF and your website into the `docs` folder. Open both, make sure they look right. Go to github.com, create a public repo, push your project from the RStudio Terminal. Go to Settings → Pages, set the source to `main` branch, `/docs` folder, save. Wait 2 minutes. Your site is live. Test it in a private window. Submit the PDF and the URL on Blackboard. Done.

Layer this over a sped-up montage of the same screen recordings. ~2 minutes total. Pin both videos in Blackboard.
